# Requirements: agrune desktop-expansion research

**Defined:** 2026-04-07
**Core Value:** AI 에이전트가 로컬 우선 환경에서 의미를 이해할 수 있는 제어 표면을 통해 브라우저와 로컬 앱을 일관되게 다룰 수 있게 만든다.

## v1 Requirements

### Inventory

- [x] **INV-01**: 사용자는 현재 agrune의 브라우저 전용 구조와 이번 연구의 macOS 확장 범위를 한 문서 묶음에서 이해할 수 있다.
- [x] **INV-02**: 사용자는 `DOM/CDP`, `macOS Accessibility`, `Apple events`, `ScreenCapture`, `Vision` 채널의 전제조건과 한계를 비교할 수 있다.
- [x] **INV-03**: 사용자는 각 채널에 필요한 권한, 보안 제약, 일반 사용자 셋업 부담을 날짜가 적힌 근거와 함께 확인할 수 있다.

### Annotation Methods Report

- [x] **ANNO-01**: 사용자는 macOS-first OS-level agrune의 어노테이션 방법 보고서에서 서로 materially different 한 3가지 직접 어노테이션 방식을 읽을 수 있다.
- [x] **ANNO-02**: 사용자는 각 직접 어노테이션 방식의 실행 모델, 필요한 앱 조건, 실패 모드를 확인할 수 있다.
- [x] **ANNO-03**: 사용자는 각 직접 어노테이션 방식이 브라우저, 네이티브 앱, 혼합 환경에서 어디까지 통하는지 confidence와 함께 확인할 수 있다.

### Annotation Alternatives Report

- [x] **ALTN-01**: 사용자는 macOS-first OS-level agrune의 어노테이션 대체 방법 보고서에서 서로 materially different 한 3가지 비-어노테이션 방식을 읽을 수 있다.
- [x] **ALTN-02**: 사용자는 각 대체 방식의 타게팅, 검증, 복구 전략과 로컬 ML 필요도를 확인할 수 있다.
- [x] **ALTN-03**: 사용자는 각 대체 방식에서 무엇이 deterministic 이고 무엇이 probabilistic 인지 명확히 구분해 볼 수 있다.

### Synthesis

- [x] **SYN-01**: 사용자는 위 6가지 케이스를 기술적 가능성, 제품 구조, 리스크, 권한/보안, 성능, UX 관점에서 한 비교 프레임으로 검토할 수 있다.
- [x] **SYN-02**: 사용자는 현재 agrune의 browser-first 구조를 기준으로 한 권장 hybrid architecture 초안을 읽을 수 있다.
- [x] **SYN-03**: 사용자는 일반 사용자 대상 관점에서 “개발자 모드 허용 + 셋업은 까다로워도 사용은 쉬움”이라는 목표가 현실적인지 판단할 수 있다.
- [x] **SYN-04**: 사용자는 구현 승인 시 어떤 프로토타입을 어떤 순서로 검증해야 하는지 우선순위를 볼 수 있다.

## v2 Requirements

### Future Expansion

- **V2-01**: Windows와 Linux에 대한 동일 연구 프레임을 확장한다.
- **V2-02**: 승인된 접근에 대해 실제 macOS 프로토타입을 만든다.
- **V2-03**: 성능 벤치마크와 앱별 지원 등급표를 만든다.

## Out of Scope

| Feature | Reason |
|---------|--------|
| macOS desktop automation 실제 구현 | 이번 사이클은 feasibility 연구가 우선이다 |
| Windows / Linux 지원 검증 | macOS 우선 범위를 유지한다 |
| 브라우저 자동화 재구현 | 현재 agrune의 DOM/CDP 경로를 전제로 확장 가능성만 검토한다 |
| 클라우드 기반 기본 OCR/비전 파이프라인 | 로컬 우선/개인정보 원칙과 맞지 않는다 |
