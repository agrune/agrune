## Overview

Inline `data-agrune-*` 어노테이션 기반 아키텍처를 완전히 폐기하고, **manifest + root-import** 기반 외부 매핑으로 피봇. 외부 사이트(YouTube 등 소스 접근 불가)와 owned React 앱(per-element 수정 불가)을 같은 manifest 메커니즘으로 자동화 가능.

핵심 결과물:

- `@agrune/manifest` SDK — 타입 안전 `defineManifest/defineTarget/defineRepeat/defineMacro` + v3 schema + zod validator
- `@agrune/react` 패키지 — `<AgruneDevtools />` root-import 1줄로 React fiber component-identity selector 활성화
- `@agrune/registry` + `agrune maps` CLI — `github.com/agrune/maps` 커뮤니티 registry foundation (seed 10개 + governance + PR bot + weekly health check)
- CDP 경로 통합 — `agrune_manifest_load` / `agrune_macro_run` MCP 도구, `preloadManifest` zero-RTT embed
- runtime 정리 — `data-agrune-*` bootstrap scanner 물리 삭제, idle boot, 문서/외부 조직 프로필 manifest 용어로 재작성
- authoring UX — DevTools `RecorderView` + `agrune manifest dev` watcher + AI authoring skill (precision 1.000 / recall 1.000, 임계 0.90/0.95)

## Milestone Summary

**Key Decisions:**

- Inline `data-agrune-*` 어노테이션 완전 폐기, manifest + root-import 기반 피봇 (2026-04-19). 외부 사이트는 소스 접근 불가, 내부 타팀 코드에 inline 요청은 PR 비용 과다 — manifest 단일 소스로 external·internal 동일 멘탈 모델 확보.
- Milestone 번호를 semver와 정렬해 v0.5로 재시작, v1.x 명명 금지 (2026-04-19). 실제 npm 0.4.1 기준으로 공식 출시 전까지 semver 준수.
- v0.5 브랜치를 main에서 격리 (`feat/v0.5-manifest`) — 대규모 피봇 폐기 가능성 대비 v1.1 브라우저 코드를 main에 안정 유지.
- `PageSnapshot v2→v3` breaking bump — backward-compat adapter 없음 (2026-04-19). 실 사용자 없음 + 버전 이관 비용 회피.
- `sensitive:true` OR-only contract — schema, 타입, validate CLI, runtime heuristic 전층에서 `sensitive:false` override 차단. 악성 manifest가 민감 필드 마스킹을 우회할 수 없도록 설계 락.
- Root-import prod 동작 2단계 guard — `AGRUNE_PROD_ENABLED` 빌드 env + `localStorage['agrune.prod.consent']` 런타임 token 동시 통과해야 bridge 활성화.
- Registry governance: `verified`/`community`/`unlisted` tier + 신규 저자 첫 3 PR 30일 holddown + maintainer 부재 기본 `disable-all` — 트래픽 붙기 전 확정.
- `~/.agrune/authoring/pending/<uuid>/` — MCP는 pending에만 쓰고 `agrune manifest dev` CLI가 유일한 사용자 소스 파일 수정 주체 (소스 파일 직접 write 금지).
