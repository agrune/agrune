    기존 `FiberIdentityIndex` 클래스에 public 메서드 `getPathByDom(el: HTMLElement): FiberIdentityPath | null` 추가.
    구현:
    1. `if (!(el instanceof HTMLElement)) return null` — defensive guard
    2. `const stored = this.domToPath.get(el); if (!stored) return null`
    3. `return stored.map(seg => ({ componentName: seg.componentName, key: seg.key, index: seg.index }))` — caller 가 반환값을 변형해도 내부 WeakMap 안전하도록 **얕은 segment 복제** (FiberPathSegment 는 primitive-only field 3 개이므로 이 방식으로 충분).

    테스트는 기존 spec 의 `makeComponentType(name)` 헬퍼를 재사용. 5 테스트를 `describe('getPathByDom (Phase 16 RECORD-01)')` 블록으로 추가.

    Decision reference: 없음 — 이 확장은 Claude's Discretion 범위. CONTEXT.md Decision A(auto targetId) 와는 직접 연관 없음.

    NOTE: fiber 자체가 GC 된 뒤(pathToRef WeakRef deref → null) 에도 `domToPath` 는 element 가 살아있는 한 유지됨. 이는 의도된 동작(element 가 DOM 에 여전히 있으면 path 반환 유효). 테스트에서 이 semantic 을 확인하지 않아도 됨 — `getByPath` 기존 테스트가 WeakRef semantic 을 이미 검증.
